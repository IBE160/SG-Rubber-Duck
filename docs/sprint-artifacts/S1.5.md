# Story S1.5: Set Up Alembic for Database Migrations

## Epic
E1: Backend & Data Foundations

## Description
As a backend developer,
I want a database migration system with version control,
So that I can safely evolve the database schema across environments.

## Technical Details

### Alembic Setup
- Initialized Alembic migration environment in `backend/migrations/`
- Configured `alembic.ini` with SQLite database URL
- Updated `env.py` to use SQLAlchemy models metadata

### Initial Migration
- Created `001_initial.py` migration file with manual schema
- Defines all tables: projects, tasks, risks, simulation_runs, event_logs
- Includes foreign keys with proper relationships
- Includes down migration for rollback capability

### Schema Coverage
The migration creates:
1. **projects table** - With indexes on name
2. **tasks table** - With foreign key to projects, indexes on text
3. **risks table** - With foreign key to projects, indexes on description
4. **simulation_runs table** - With foreign key to projects
5. **event_logs table** - With foreign key to simulation_runs, indexes on event_type

### Database URLs
- Development: SQLite at `./app.db` (file-based)
- Configurable via environment variable `DATABASE_URL`

## Usage

### View migration history
```bash
cd backend
alembic history
```

### Upgrade to latest migration
```bash
alembic upgrade head
```

### Downgrade to base
```bash
alembic downgrade base
```

### Create new migration after model changes
```bash
alembic revision --autogenerate -m "Description of changes"
alembic upgrade head
```
