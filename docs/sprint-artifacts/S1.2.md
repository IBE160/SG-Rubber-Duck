# Story S1.2: Define SQLAlchemy Models

## Epic
E1: Backend & Data Foundations

## Description
As a backend developer,
I want to define SQLAlchemy models for the core entities,
So that I have a structured data layer to persist project, task, risk, simulation run, and event data.

## Technical Details

### Models Implemented
1. **Project** - Main project entity with budget and timeline
2. **Task** - Individual tasks within a project, supporting dependencies and sub-tasks
3. **Risk** - Risk factors that can impact project tasks
4. **SimulationRun** - Represents a single simulation execution with status tracking
5. **EventLog** - Records events that occur during simulation execution

### Key Features
- Proper foreign key relationships and cascading deletes
- JSON columns for complex data (dependencies, affected tasks, simulation results)
- DateTime tracking for simulation lifecycle (created_at, started_at, completed_at)
- Support for simulation parameters (seed, critical path, duration, cost)

### Pydantic Schemas
- Created corresponding Pydantic schemas for all models
- Schemas support both creation and read operations
- Proper serialization/deserialization with `model_config`
